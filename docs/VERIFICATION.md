# 本次上线核查

## 已覆盖的业务

- 所有代理只登录 CCMAX；上号目标始终是管理员配置的上游主账号，不为下级创建上游登录账号。
- 固定父子关系，可逐层开通下级、管理直属下级状态与密码；上级查看整条下级团队，兄弟团队隔离。
- 相同 Claude 邮箱可接入多个平台连接；新填写的邮箱只占位，完成真实平台授权或管理员核实分配后才获得数据与收益归属。
- Gatelink / AI008 / Mini CC Gateway 的账号列表、实时快照、可用上号配置和启停操作由服务器适配。AI008 和 Mini CC 支持 RT 和历史查询；平台连接凭据、一次性授权资料加密存储，敏感任务执行后清理。
- 每个平台的 0–1 结算折扣独立设置，上游合同价按连接留档。初始价格可填写真实合同起始日，后续改价从次日北京时间生效；已有用量保留价格快照。
- 每个账号、连接、日期只保留一条用量，重复实时同步替换预估值。历史用量人工核对后封账，按各层价格计算应收、下级应付和本人利润。
- 用量查询使用服务端分页及完整筛选合计；团队页面按期间展示本人和团队账号数、分支用量及本层收益。
- 账单确认必须从上游到下级逐层进行，唯一开票明细和唯一利润流水防止重复入账。
- 提现仅可用本人已确认利润，行锁防并发超提，请求编号防网络重试重复冻结；收款信息加密，只有申请人及其直属付款上级可读取。
- 提现由直属上级人工处理，驳回一次性释放；平台管理员也可记录本人利润的外部提取。
- 已封账用量和收益、已确认账单、已处理提现在数据库层防改写；流水、审计和开票明细只追加。

## 验证方式

`npm test` 使用临时 PGlite；指定 `TEST_DATABASE_URL` 后，同一组安全和账目测试改用真实 PostgreSQL，每项测试隔离在独立临时 schema，结束后删除。不要把生产库作为测试库。

旧版本迁移仅依据已有管理员分配或成功授权的审计记录确认归属；仅凭邮箱占位和同步绑定不会自动获得归属，存在封账历史的账号也不能改挂。

覆盖四层代理、两个平台、微额舍入守恒、历史价格、重复/冲突封账、逐级确认、兄弟隔离、停用父级、邮箱冒领、任务幂等、提现并发和驳回防重。适配器测试验证分页、缺失用量、真实邮箱核对、OAuth state 和错误信息脱敏。

此前核查的 19 项账目、安全、适配器和迁移测试在真实 PostgreSQL 上通过，Chromium 流程测试通过；编译后的生产入口也验证了 PostgreSQL 自动迁移、首次管理员创建、健康检查、登录、数据接口、SPA 页面及安全策略。生产依赖审计没有已报告漏洞；开发依赖另有一项 esbuild Windows 开发服务器的低危通告，不用于生产服务。

### Mini CC Gateway 接入核查（2026-10-18）

- 真实主账号验证：登录和 Cookie 会话、账号列表、默认策略和 CC 模板、按北京时间查询昨日历史、生成 OAuth URL / state 均成功。当前该主账号返回 0 个账号，因此真实账号的 OAuth 回调、RT 导入、启停和非零用量尚未端到端验证；没有向真实平台提交或停用 Claude 账号。
- 适配器按 `upstream_id` 建立绑定，读取顶层 `daily_cost`、`cost_7d` 和 `cost_30d`；缺失或负数用量不会被当作零。按上游声明的页数读完整账号列表。
- 新建账号强制读取上游默认模板与可用分组；不接受前端改写其固定策略。RT / OAuth 交换后读取账号详情核对真实邮箱，提交时的名称不是归属证明。OAuth 回调必须携带匹配的 state。
- 历史查询需 `complete=true` 且没有 pending / refreshing 才返回待审核记录；不完整、负数、重复账号或缺失金额不会生成结算候选；未出现的账号不自动补零。
- 数据库第 4 版迁移增加独立的 `minicc` 平台，已有报价和封账记录保留。每一层需明确设置新平台初始报价；已有报价修改仍仅从次日生效。测试覆盖缺价回滚、分层不同折扣、跨平台利润隔离和历史价格固定。
- 本次 31 项自动测试在 PGlite 和 PostgreSQL 17 均通过，生产构建通过，2 项 Chromium 流程测试通过；浏览器额外覆盖新增平台选择、固定模板、RT 目标和历史查询入口。浏览器和账号写入使用隔离测试数据，真实上游仅进行上述验证。

`npm run build && npm run test:e2e` 在隔离测试数据上用 Chromium 操作登录、创建代理、代理继续创建下级、团队与用量查看、账单确认、提现及手动打款。浏览器测试不会向真实上游写入账号。

GitHub Actions 配置 PostgreSQL 17 服务执行测试、生产构建、Chromium 测试和 Docker 镜像构建。本地没有 Docker，容器构建以 Actions 的实际结果为准。

## 运营边界

- 多平台一键上号是批量生成授权、批量提交各自的回调；每个平台的 OAuth 授权不能共用同一个一次性 code，仍需账号持有人完成授权。真实账号的全流程需持有人配合，上游接口变化也可能需要更新适配器。
- Gatelink 当前代理权限不能读取已结束日期的完整历史日账单。必须向上游取得逐账号日账单导入；系统不会把未核实的实时快照自动当作可提现收入。
- AI008 历史查询也是待审核数据；核对日期、归属、金额完整性后才能封账。
- 当前透传范围是账号上号、状态、用量与对账数据。并非复制上游所有管理页面；不提供模型 API 请求网关。
- 美元账本记录收益分配与提现义务，不托管资金、不自动转账。上级确认账单不代表已实际付款；各层应保留下级应付款准备金，按真实线下收付登记凭证，不可把下级应付当成本人利润提取。
- 已确认数据不能直接覆盖。发现上游封账后纠错时，应暂停相关付款，留存原账单及差额说明，并由维护人员设计独立冲正记录；当前界面不提供任意改写已结算数据的入口。
- 财务流水界面展示最近 20 条，可导出本人全部流水；单次用量或流水导出上限 100,000 条，超限会明确报错，不生成截断文件。
- Railway 正式运营应使用 PostgreSQL 自动备份，保管原 ENCRYPTION_KEY，并监控同步失败、待核对任务及异常/负利润。建议先小规模真实账号试运营并逐笔核对一次完整收款和提现周期。
