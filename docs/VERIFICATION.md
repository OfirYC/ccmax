- 账单确认必须从上游到下级逐层进行，唯一开票明细和唯一利润流水防止重复入账。
- 提现仅可用本人已确认利润，行锁防并发超提，请求编号防网络重试重复冻结；收款信息加密，只有申请人及其直属付款上级可读取。
- 提现由直属上级人工处理，驳回一次性释放；平台管理员也可记录本人利润的外部提取。
- 已封账用量和收益、已确认账单、已处理提现在数据库层防改写；流水、审计和开票明细只追加。

## 运营边界

- 多平台一键上号是批量生成授权、批量提交各自的回调；每个平台的 OAuth 授权不能共用同一个一次性 code，仍需账号持有人完成授权。真实账号的全流程需持有人配合，上游接口变化也可能需要更新适配器。
- Gatelink 当前代理权限不能读取已结束日期的完整历史日账单。必须向上游取得逐账号日账单导入；系统不会把未核实的实时快照自动当作可提现收入。
- AI008 历史查询也是待审核数据；核对日期、归属、金额完整性后才能封账。
- 当前透传范围是账号上号、状态、用量与对账数据。并非复制上游所有管理页面；不提供模型 API 请求网关。
- 上游返回代理 ID 可以检测 ID 漂移；隐藏的认证信息变更，以及 Gatelink 旧账号代理变更无法自动完整核实。管理员需在上游检查实际出口；已固定代理不支持直接换绑，迁移需另行实施逐平台更新和核验。「禁止上号」不等同于停用现有上游账号。
- 美元账本记录收益分配与提现义务，不托管资金、不自动转账。上级确认账单不代表已实际付款；各层应保留下级应付款准备金，按真实线下收付登记凭证，不可把下级应付当成本人利润提取。
- 已确认数据不能直接覆盖。发现上游封账后纠错时，应暂停相关付款，留存原账单及差额说明，并由维护人员设计独立冲正记录；当前界面不提供任意改写已结算数据的入口。
- 财务流水界面展示最近 20 条，可导出本人全部流水；单次用量或流水导出上限 100,000 条，超限会明确报错，不生成截断文件。
- Railway 正式运营应使用 PostgreSQL 自动备份，保管原 ENCRYPTION_KEY，并监控同步失败、待核对任务及异常/负利润。建议先小规模真实账号试运营并逐笔核对一次完整收款和提现周期。
