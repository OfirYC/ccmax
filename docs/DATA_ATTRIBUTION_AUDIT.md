# 数据归属与展示核对

## 统计口径

- Claude 账号的已核实 `owner_id` 决定本人归属。上级可见本人的全部下级层级；兄弟团队互不可见。仅填写邮箱的待核实账号不能取得上游数据或收益。
- 同一 Claude 账号在不同平台连接的调用分别统计。团队账号数按 Claude 账号去重，平台账号数按绑定计数；不能把各层代理的团队小计相加当作全平台总计。
- 模型调用中的成员行按账号的直接归属者分组，成员行相加等于当前筛选总计。代理团队页面每个成员的财务行则包含其全部下级，并展示该成员本层应收、应付、利润；不同层级行存在包含关系。
- 首页平台卡片、账号列表今日金额、模型调用当前汇总使用相同的有效快照和北京时间日期判断。过期、缺失、停用平台和跨日的今日金额显示缺失，不用最后保存的金额或零代替。账号调用详情保留历史快照时间，跨日的“今日”计数不显示。
- 平台上游各自报告的请求数、Token、金额可能来自不同缓存。RPM/TPM 是采样；趋势是历史采样，可能包含后来移除或停用账号当时的观测，不等同于当前汇总。
- 管理员的平台运营汇总含待归属账号，代理只能看到已核实团队数据。首页累计账单与收益是已分配到收益链的财务数据。运营快照消费与已封账财务金额不能直接混加。

## 本次修复

1. 首页和账号列表不再把 `bindings.daily_usd` 的最后一次值直接当作今日金额。空平台仍显示，平台已有其他团队账号也不会让该平台从当前用户首页消失。
2. Gatelink 上游缓存属于昨日或没有可核实源时间时，同步保留账号快照，但跳过当日财务预估；任务结果 `skippedDaily` 表明跳过数量。旧缓存不被自动封成历史账单。
3. 管理员确认账号归属时，在同一事务补全该账号所有未封账日期的收益链，保留原金额和冻结价格。缺少任何一层历史合同价会整体回滚，需补齐真实价格后重试。
4. 已封账记录及流水不被重写；既有错误日记录不能根据当前值推测修复。应结合原平台逐账号、逐日账单核对。
5. 上游列表分页重复、总数变化、声明总数与结果不符、缺少邮箱时，整次同步失败并保留上次数据，防止不完整列表覆盖账号状态。
6. 并行刷新时只接受最新请求结果，避免旧响应覆盖新快照；模型消费缓存跨北京时间零点即停止计入今日消费。延迟的模型缓存保留为带原始时间的参考值，独立于当前有效模型汇总，不计入结算；页面以非实时提示区分。

## Railway 只读检查

部署最新 main 后，在 Railway 连接应用容器的终端执行：

```sh
npm run audit:data
npm run audit:finance
```

两个命令都已编译到生产镜像，无需安装开发依赖。使用应用已有的 `DATABASE_URL`，事务为 `REPEATABLE READ, READ ONLY`，不会迁移数据库、修改归属、补记流水或调用上游。

`audit:data` 检查代理父子链、已归属账号所有未封账及已封账用量的完整收益链、每层冻结金额与差价；未归属用量不允许存在收益或封账。报告同时包含库存数量、待归属数量和当前运营快照覆盖率。异常返回非零退出码，仅输出记录 ID 和金额，不输出上游凭据或账号邮箱。

`audit:finance` 继续核对已封账明细、待确认账单、确认回款、利润流水和提现来源。若发现旧的已归属但未分配预估，用原始逐日账单核实并从「用量明细 → 核实日账单」处理；不得用今天的缓存金额补历史。缺少历史报价须先补齐真实合同起始价。已封账冲突应人工对账，不能覆盖历史。

本地执行需先 `npm run build`。代码与隔离数据库测试不等于已检查线上实际账单；只有对线上数据库运行命令并核对上游原始账单，才能确认该实例的历史数据。

## 验证范围

独立测试使用不同账号和不同金额，覆盖四级代理、兄弟团队、同账号三平台连接、同类平台两个主连接、本人/全部下级筛选、待归属、过期、移除与停用账号、查询分页、跨零点快照，以及未封账归属补全和失败回滚。各层原始账单不能重复相加；每笔收益链的本层利润之和等于根层应收。

## AI008 数据显示

首页平台卡片同时显示今日与近 7 天消费、有效快照覆盖和待归属数量，点击进入对应连接近 7 天的模型调用。管理员“全平台账号”包含待归属运营数据；本人和代理团队收益仍只取已核实归属。今日为零时提示是上游返回值，并可切换近 7 天。

模型分类接口可能返回旧的 `generated_at`：保留按账号 ID 匹配的缓存及时间，API 的 `models[].value` 仍仅汇总当前有效模型值，`models[].reference` 提供最近可用缓存汇总、覆盖和最早/最晚源时间。页面使用缓存参考值时明确标记非实时。跨日的今日模型缓存不用于今天的参考值。
