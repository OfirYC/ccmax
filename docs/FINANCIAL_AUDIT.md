# 代理资金链路核查

本次核查覆盖用量、冻结价格、逐层应收/应付/利润、账单及明细、利润流水、提现冻结、付款登记和驳回。系统账本以 USD 记账，保留 8 位小数；折扣为每个平台独立的结算系数。

## 计算与资金边界

同一用量在每层的应收为 `round(平台原始账单 × 当层冻结折扣, 8)`。下级应付取下一层的已舍入应收，利润为两者之差。例如原始账单 $100、价格链 `0.5 → 0.2 → 0.1`，各层利润分别为 $30、$10、$10，总计 $50，等于平台应收。同价时该层利润为零。缺价阻止入账；倒挂保留原合同，如实记录负利润，来源和公式核对无误后可逐级结算，扣减本人余额。负余额不能新申请提现，后续利润先抵扣亏损。

可提现余额仅为本人已确认利润减去申请提现的冻结金额，再加上已驳回申请的退回金额。确认打款后不重复扣款；驳回仅释放一次，释放必须有等额、同一用户的原冻结流水。下级应付不会进入本人的可提现余额；`GET /api/finance` 另外返回已确认上游应收总额和直属下级待付款准备金，供付款人准备团队款项。兄弟分支和其他用户的钱包独立核对。

账单只能包含已封账且尚未开票的日收益，确认前复核整条冻结收益链、每层付款关系、金额公式、明细归属和汇总。直属下级账单的每条用量都必须已有确认的上级账单覆盖；上下级账单日期范围可以不同。已确认账单重复确认不重复记利润；提现审核使用相同决定和凭证重试时返回原结果，冲突决定被拒绝。

## 本次修复

| 问题 | 修复 |
| --- | --- |
| PostgreSQL 默认把 DATE 转为本地午夜时间，UTC 格式化时可能偏移一天 | 数据库边界将 DATE 原样读取为 `YYYY-MM-DD`，时间戳仍保留真实时刻；覆盖次日调价和多个时区 |
| 确认前只检查倒挂，未完整核对账单明细及正数异常金额 | 复算冻结价格和完整祖先链，并核对归属、付款人、日期、应收、应付、利润和汇总；空账单也拒绝入账 |
| 旧余额或提现可能缺少真实来源 | 提现和审核前核对全部本人流水来源、已确认账单及冻结/释放记录；不一致时阻止后续操作 |
| 新流水只有引用编号，没有来源约束 | 第 7 版迁移为新增账本、开票明细增加来源触发器，阻止封账后新增收益；不改写旧账 |
| 查询余额和冻结额用了不同 SQL 快照 | 合并为一条 SQL 读取；余额写入继续使用用户行锁，重复记账由唯一约束兜底 |
| 网页大金额先转换为浮点数，可能显示错误 | 直接格式化十进制金额字符串，保留完整金额；验证 24 位金额、8 位小数和舍入边界 |
| 多条合法用量合计可能超出单张账单的数据库金额范围 | 开票前明确报错，要求缩短期间；事务内无部分账单或明细残留 |

第 8 版迁移允许与已确认账单利润完全相等的负数结算流水，保留账单来源、归属、冻结和释放约束，不重写历史记录。后来确认的亏损占用先前提现余额时，禁止登记打款，可驳回释放原冻结。

## 核对现有账本

「账单结算」的「我的结算进度」按北京时间截至昨日列出全部历史数据，分别显示已封账待开票应收、已归属待核实原始用量，以及仅管理员可见的待归属原始用量。三个状态互斥；后两项不是收益，不能提现。已开票的用量不再计入待开票应收。

开票前可选择本人或直属下级和日期范围，预览各平台原始金额、冻结应收、下级应付和利润，统一保留 8 位美元小数。`GET /api/invoices/preview` 在只读、可重复读事务中检查收益链，不分配归属、不封账、不创建账单，也不入钱包。代理只能查看自己或直属下级的开票预览，平台主账号名称继续隐藏。

网页开票提交预览摘要；如果可开票明细发生变化，返回 409 并要求刷新预览，而不创建金额过时的账单。生成账单仍须经过独立的回款确认才能记入利润。原有 API 开票参数继续兼容，自动集成也可提交预览返回的 `previewToken` 进行同样校验。

每位用户可在「利润提现」点击「核对资金账本」，或通过具有 `read` 权限的 API 密钥请求 `GET /api/finance/check`。只核对当前用户，成功返回 `{ok:true, balance, checkedAt}`；异常返回 409 及业务错误码。提现和审核也会自动进行同样的核对。

管理员在账单更新记录的详情中可以提交已核对的日终快照依据，调用 `POST /api/billing/finalize-snapshot` 将已结束日期的 `live_snapshot` / `daily_snapshot` 归档为已核实的最终日账单，并自动生成各层待确认账单。该操作要求核实说明，清除快照预估标记并保留审计记录；没有可用快照或存在计数回退时不会封账。

管理员可在「账单结算」或「利润提现」点击「全平台资金核对」。`GET /api/finance/audit` 仅允许管理员网页登录，普通代理及 API 密钥均不能访问。它在只读、可重复读事务中核对全部钱包、待确认账单、已封账和已归属的预估收益链，并检查待归属账号是否错误产生收益。发现异常时返回 `ok:false` 和记录编号，保留原始账本。

报告按代理列出可提现、冻结、已确认利润和已付款提现；按平台连接列出已归属/全部绑定、已结束日期待核实金额、已封账原始金额和管理员尚未开票的应收。原始用量按平台绑定只计算一次，不能把各代理重复包含下级的团队账单相加。今日预估不进入“历史待核实”，待归属数据不虚构任何代理利润。核对入口不会创建账单、确认收款、分配账号或处理提现。

运维人员可以使用目标 PostgreSQL 的 `DATABASE_URL` 执行：

```bash
npm run audit:finance
```

此命令与网页共用同一核对实现，在一个只读、可重复读事务中核对全平台钱包、待确认账单、已封账和预估用量，输出 JSON；发现问题时退出码为 1。不执行迁移或开户，不修改余额、合同、账单或提现状态，不需要上游账号或加密密钥。`usage_batch` 异常列出该批候选用量编号，需进一步核对原始记录。

## 历史账单来源校验

Gatelink 新上号记录可能在列表中返回空的当日金额。此时同步保留账号及其可用遥测，缺失金额保存为 `null`，跳过该账号当日预估入账，其余有效账号继续同步；负数或格式错误仍会拒绝同步。第 10 版迁移仅允许运营快照金额为空，不更改用量、收益、账单或钱包。任务列表及详情明确提示未采集数量，账号金额仍显示为缺失，不能当作零美元结算。

AI008 历史结果必须带有可核对的任务编号、分页账号数、页大小和当前页；若返回原始查询日期，必须匹配本次北京时间日期。后续分页必须保持同一任务、日期、总数和页大小。重复账号、缺失/负数/非有限金额、超范围金额或不完整页均拒绝生成导入候选；不使用共享汇总给账号分摊消费。Mini CC 使用同一逐账号金额及重复检查，并等待上游完整性标记后才接受结果。每日任务对通过校验的完整查询结果自动封账并生成待确认账单；额外查询和导入仅保留运维接口，页面无需手动采集或生成。

2026-10-19 北京时间线上只读复核：三个平台登录、账号列表与上号配置接口均可访问；早期核查时 Gatelink 4 个账号、AI008 9 个账号、Mini CC 0 个账号。AI008 和 Mini CC 的已结束日期历史查询可正常完成，Gatelink 当前代理权限无法读取完整历史；第 12 版在授权开启时按有效日终快照预估出账，第 13 版可恢复已有旧日用量快照；完全没有保存的日期仍需上游日账单。线上尚无已归属收益、结算账单或提现业务，不能把空账本的校验通过等同于已经完成真实收付款验证。AI008 的历史确认金额与原实时预估存在差额，应以通过完整性校验的日账单封账，不能直接把旧预估记成已收到的利润。

第 12 版每日任务在北京时间 02:00 后自动读取昨日完整历史，按历史价格和已核实归属封账、创建每层待确认账单。来源先单独归档，缺归属、缺价或已封账冲突按账号隔离，不阻塞其他有效账号；自动开票跳过尚未处理或存在冲突的来源记录，重试不重复开票。

独立快照 worker 全天每 5 分钟采集，23:55 至次日 00:10 每分钟采集；失败账号重试，保留最后有效来源及采集时间。每日任务仍优先直接读取完整日账单，仅实际 403/404 才采用快照兜底。第 13 版允许恢复旧版 `live_snapshot` 同日观测，保留真实观测时间及恢复来源，不虚构原本缺失的上游时间。选择同日末次有效观测，不取最大值，不把下一日清零值算给昨日；计数回退仍需核对。快照预估和原始金额独立归档，账号未归属时也保留来源账单，归属确认后自动生成收益链。没有任何观测时状态为待补齐，金额显示缺失，不生成零元账单。预期的权限回退诊断独立保存，不冒充账单失败。
